---
name: Item Performance product category mapping
description: Where SKU -> category data comes from and how the category filter works
---

Product categories for Item Performance SKUs come entirely from a generated
file, `artifacts/api-server/src/lib/sku-categories.ts`, derived from a
user-supplied CSV mastersheet (SKU, Title, Product Type, UPC). There is no
category-detection logic from product names/keywords and no "Other" bucket.

**Why:** product decision — categorization must come only from the mastersheet
the user maintains; a SKU not present in it has no known category.

**How to apply:**
- Any SKU returned by the live Item Performance data (NetSuite sell-in,
  Target/Walmart/Circana POS) that has no entry in the SKU category map is
  dropped from the API response entirely — never shown uncategorized or
  bucketed as "Other".
- One mastersheet row used a non-canonical label ("Claw  Clip", double space,
  singular) — normalize any such variant to the canonical category name
  before using it as a filter value.
- The category filter replaced an old, non-functional set of toggles (All
  SKUs / Above-Below Retail Avg / Above-Below Target Benchmark) that never
  actually filtered the table on either the client or server.
- When the user supplies an updated mastersheet, `sku-categories.ts` needs to
  be regenerated by hand (no automated re-import pipeline exists yet).
